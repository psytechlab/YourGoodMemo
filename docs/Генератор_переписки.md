# Генерация синтетических диалогов

## Описание

Генератор синтетических диалогов с эталонной разметкой, которые будут использоваться для тестирования и исследования
работы агента.

Диалоги должны содержать релевантные фрагменты, соответствующие заданным точкам опоры, так и филлеры. При генерации заранее фиксируется, в каких частях диалога и какие точки опоры должны проявляться.

Это позволяет сравнивать точки опоры, заданные при генерации, с теми, которые обнаруживает агент, и оценивать:

-насколько точно агент определяет начало и границы релевантных фрагментов;
-правильно ли классифицирует их по типам точек опоры;
-какие точки опоры он пропускает.

## Реализация

Для каждого диалога заранее задаются:

-точки опоры, которые должны проявиться;
-порядок и длительность их проявления;
-директивы для клиента и собеседника.

Помимо целевых фрагментов, генератор самостоятельно создаёт филлеры — нейтральные и бытовые сообщения, не связанные с заданными точками опоры. Они имитируют обычную переписку и позволяют проверить, способен ли агент выделять релевантные фрагменты среди большого количества нерелевантного контекста.

## Эталонная разметка

Для каждого сгенерированного диалога сохраняется информация о том:

- какие точки опоры были заложены в сценарий;
- какие сообщения относятся к каждой точке опоры;
- где начинается и заканчивается релевантный фрагмент;
- какие сообщения являются филлерами;

Таким образом, результат генерации состоит не только из текста диалога, но и из его эталонной разметки, необходимой для сравнения результата работы агента с известным правильным ответом.

## Текущая реализация

Промпт второго участника изменён с роли психолога на роль близкого поддерживающего друга, чтобы генерируемые диалоги  соответствовали задаче анализа обычной личной переписки.

Генератор состоит из заданного персонажа, набора директив в situations.yaml, компонента Reasoner и LLM. При генерации LLM получает промпт с описанием роли, историю уже сгенерированного диалога и директиву текущего шага. За счёт этого генерация учитывает предыдущие реплики и сохраняет связность диалога.

Диалог генерируется пошагово: Reasoner выбирает директиву, после чего LLM получает системную инструкцию, историю диалога и текущую директиву и генерирует очередную реплику. История передаётся на следующих шагах, поэтому генерация учитывает предыдущий контекст.

## Дальнейшее развитие

Переход от случайного выбора директив к управляемому формированию сценария переписки. Для каждого сценария заранее будут задаваться точки опоры, порядок и длительность их проявления, а Reasoner будет управлять их реализацией в ходе генерации.

Передача директивы обеим сторонам диалога — клиенту и собеседнику. Это позволит контролировать не только состояние или поведение клиента, но и необходимые реакции второго участника, например поддержку, проявление эмпатии и т. д.
